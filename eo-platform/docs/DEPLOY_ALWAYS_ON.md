# تشغيل البوت دائمًا (24 ساعة) — دليل مبسّط

> البوت يعمل على كل الأجهزة تلقائيًا (أي جوال أو كمبيوتر يفتح @EO_PredictorBot).
> الشيء الوحيد الذي يجب أن يبقى شغّالًا هو «المحرّك». يحتاج جهازًا يعمل 24 ساعة.

## الأسهل: خادم سحابي (Railway كمثال)

لا أوامر ولا برمجة. فقط:

1. ادخل **railway.app** وسجّل دخول بحساب GitHub.
2. اضغط **New Project → Deploy from GitHub repo**، واختر المستودع `wswmth39-hash/-`.
3. Railway يكتشف ملف `Dockerfile` ويبني المشروع تلقائيًا.
4. في **Variables** أضف هذه المتغيرات (فقط هذه):

   | المتغير | القيمة |
   |---|---|
   | `EO_TELEGRAM_BOT_TOKEN` | رمز البوت من BotFather |
   | `EO_TELEGRAM_ALLOWED_USERS` | معرّفك الرقمي (مثل `5942544919`) |
   | `EO_SIGNAL_STYLE` | `image` |
   | `EO_TELEGRAM_ACCESS_CODE` | الرمز السري الذي تريده |
   | `EO_ENABLE_BINANCE` | `true` |
   | `EO_ADMIN_PASSWORD` | كلمة مرور لوحة التحكم |
   | `EO_SESSION_SECRET` | أي نص طويل عشوائي (يُستخدم للتشفير) |

5. أضف **Volume** (قرص دائم) على المسار `/data` حتى لا تضيع البيانات عند إعادة التشغيل.
6. اضغط **Deploy**. خلال دقائق يعمل البوت، ويبقى شغّالًا 24 ساعة، على كل الأجهزة.

**مهم:** لا تضع الرمز في الكود ولا على GitHub — فقط في Variables داخل Railway.

## بدائل بنفس المبدأ
- **Render / Fly.io / أي VPS** (مثل Hetzner أو DigitalOcean): نفس الفكرة — اربط المستودع أو ارفع الكود، واضبط المتغيرات أعلاه. على VPS يكفي:
  ```bash
  docker compose up -d
  ```
  (ملف `docker-compose.yml` جاهز، ويعيد التشغيل تلقائيًا.)

## على كمبيوتر ويندوز في بيتك (مجاني)
- يعمل ما دام الكمبيوتر مفتوحًا. الخطوات الكاملة في `docs/TELEGRAM.md` (قسم Task Scheduler): يشتغل تلقائيًا مع تشغيل ويندوز، ويعيد المحاولة إن توقف.

## جهاز صغير دائم (أرخص حل)
- جوال أندرويد قديم مع تطبيق Termux، أو جهاز Raspberry Pi، تتركه متصلًا بالكهرباء والإنترنت.

## ملاحظات
- **النموذج اللغوي (Qwen) اختياري** ولا يلزم لوضع الإشارة؛ يمكن تشغيل البوت بدونه على خادم صغير.
- بعد النشر: افتح `https://<عنوان-خادمك>` للوحة التحكم (غيّر الرمز، احظر مستخدمين…).
- الرمز السري والمستخدمون يُداران من اللوحة بعد التشغيل.
