# بوت Telegram العربي (EO_PredictorBot) — الإعداد والتشغيل

> **EO_PredictorBot أداة تحليل مستقلة، غير تابعة لشركة ExpertOption ولا مرتبطة بها ولا معتمدة منها.**
> يظهر هذا التنبيه في رسالة الترحيب وفي المساعدة وفي نهاية كل نتيجة تحليل.

البوت جزء من المنصة نفسها:

* يعمل **داخل** `python -m eoplatform serve`، ويستخدم محرك التحليل وقاعدة البيانات وكتالوج الأسواق ذاتها. لا يوجد محرك منفصل.
* يتصل بـ Telegram بطريقة «الاستطلاع الطويل» (long polling)، فلا يُفتح أي منفذ ولا تُكشف أي واجهة داخلية على الإنترنت.
* يعمل في **المحادثات الخاصة فقط**: يتجاهل أي رسالة أو زر من مجموعة أو قناة دون أي رد (ولا حتى رسالة «غير مصرّح»، لأنها تكشف معرّف المستخدم لأعضاء المجموعة)، ويغادر تلقائيًا أي مجموعة يُضاف إليها.

## ما الذي تحقق منه وما الذي لم يُتحقق منه

| | الحالة |
|---|---|
| كل الأوامر والأزرار والتحليل والحالات الخاصة | ✅ مختبرة: 22 اختبارًا تشغّل مكتبة python-telegram-bot الحقيقية وجوهر المنصة الحقيقي مقابل خادم Bot API محلي مُحاكى |
| المحادثات الخاصة فقط، مغادرة المجموعات، كشف التعارض 409، رسالة «قيد التحميل» | ✅ مختبرة بالطريقة نفسها، ومُجرّبة مع `serve` كاملًا ولوحة التحكم في متصفح Chromium |
| الاتصال الحقيقي بـ `api.telegram.org` | ⚠️ **لم يُتحقق منه هنا**: شبكة بيئة البناء تحجب Telegram (رد البروكسي 403، مُثبت بالأمر `telegram-check`)، ولا يوجد رمز بوت حقيقي. تحقق بنفسك بالخطوة 4 أدناه |

## 1. إنشاء البوت عبر BotFather

1. افتح Telegram وابحث عن **@BotFather** (الحساب الرسمي، عليه علامة توثيق زرقاء).
2. أرسل `/newbot`.
3. اكتب اسمًا يظهر للمستخدمين، مثل `EO Predictor`.
4. اكتب اسم المستخدم **`EO_PredictorBot`** (يجب أن ينتهي بـ `bot`؛ إن كان محجوزًا اختر غيره، وستُنبّهك المنصة في سجل الأحداث بأن الرمز يخص بوتًا باسم آخر).
5. سيعطيك BotFather **رمز البوت** (token) بهذا الشكل: `123456789:AAH...`. **احفظه سرًّا**؛ من يملكه يتحكم في البوت.
6. أرسل `/setjoingroups` ← اختر البوت ← **Disable**، فلا يمكن إضافته إلى أي مجموعة أصلًا (البوت يغادر المجموعات تلقائيًا على أي حال).
7. مُستحسن: `/setdescription` و`/setabouttext` بنص مثل:
   «أداة تحليل مستقلة للأسواق — غير تابعة لشركة ExpertOption. تحليل فقط، لا تداول حقيقي.»
   الأوامر نفسها (`/start` و`/markets`…) يسجّلها البوت تلقائيًا عند التشغيل.

إن تسرّب الرمز: `/revoke` في BotFather ثم ضع الرمز الجديد في `.env`.

## 2. معرفة معرّفك في Telegram (للسماح لك وحدك)

البوت **يرفض الجميع** ما لم يكن معرّفهم في `EO_TELEGRAM_ALLOWED_USERS`.

أسهل طريقة لمعرفة معرّفك:

1. شغّل البوت مرة (الخطوة 5).
2. أرسل له `/start`.
3. سيرد: «غير مصرّح… معرّفك: 123456789».
4. انسخ الرقم إلى الإعدادات وأعد التشغيل.

## 3. الإعدادات (ملف `.env` داخل مجلد `eo-platform`)

```ini
EO_TELEGRAM_TOKEN=123456789:AAH-ضع-الرمز-هنا   # أو EO_TELEGRAM_BOT_TOKEN (الاسمان مقبولان)
EO_TELEGRAM_ALLOWED_USERS=123456789          # عدة مستخدمين: 111,222,333
```

* لا تضع الرمز في الكود، ولا ترفعه إلى GitHub (`.env` مستبعد من git).
* يُحذف الرمز تلقائيًا من كل السجلات.
* المستخدمون يُخزَّنون كبصمة مشفّرة (hash)، لا كأرقام Telegram.

## 4. التشغيل على Windows خطوة بخطوة (PowerShell)

```powershell
# مرة واحدة: Python 3.11+ من python.org (فعّل "Add python.exe to PATH")، وGit، وOllama من ollama.com
git clone -b ccr-bd054d15-g35iy3 https://github.com/wswmth39-hash/-.git eo-bot
cd eo-bot\eo-platform
py -3.11 -m venv .venv
.venv\Scripts\Activate.ps1          # إن رُفض: Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
pip install -e vendor/TradingAgents -r requirements.txt
copy .env.example .env
notepad .env                        # أضف EO_TELEGRAM_TOKEN وEO_TELEGRAM_ALLOWED_USERS
ollama pull qwen3.5:9b              # اختياري لفريق الوكلاء؛ البوت لا يحتاجه
python -m eoplatform create-admin   # كلمة مرور لوحة التحكم
python -m eoplatform telegram-check # يتحقق فعليًا من الرمز والاتصال بـ Telegram
python -m eoplatform serve          # المنصة + البوت معًا
```

**الأمر `telegram-check`:**

* عند النجاح يطبع `OK — token valid, API reachable` واسم البوت.
* إن فشل يطبع السبب الحقيقي: رمز خاطئ، أو شبكة محجوبة، أو جدار حماية.

**بعد التشغيل:** افتح البوت في Telegram وأرسل `/start`.

**تشغيل تلقائي مع Windows (Task Scheduler):**

1. افتح «Task Scheduler» ← «Create Task».
2. **General:** فعّل «Run whether user is logged on or not».
3. **Triggers:** «At startup».
4. **Actions** ← «Start a program»:
   * Program: `C:\path\to\eo-bot\eo-platform\.venv\Scripts\python.exe`
   * Arguments: `-m eoplatform serve`
   * Start in: `C:\path\to\eo-bot\eo-platform`
5. **Settings:** فعّل «If the task fails, restart every 1 minute».

**البديل:** Docker Desktop مع `docker compose up -d`. يعيد التشغيل تلقائيًا، وضع متغيرات Telegram في `.env`.

## 5. استخدام البوت

| | |
|---|---|
| `/start` | «مرحباً بك في EO_PredictorBot» + تنبيه عدم التبعية لـ ExpertOption + «اختر السوق الذي تريد تحليله»، مع أزرار الأسواق |
| `/markets` | كل الأسواق المدعومة (تُقرأ من كتالوج المنصة، 8 في الصفحة، فلتر عادي/OTC). `/markets eur` للبحث، أو اكتب اسم السوق مباشرة |
| الضغط على سوق | تحليل فوري لكل المدد (30 ث، 1 د، 2 د، 5 د) بمحرك المنصة |
| `/status` | حالة استطلاع البوت (ومنها تعارض 409)، والمصادر المتصلة فعليًا، والنماذج المفعّلة، والاختبارات المستقبلية |
| `/history` | آخر تحليلاتك ونتائجها الحقيقية بعد انتهاء المدة |
| `/help` | المساعدة |

**كيف يُختار القرار والمدة:**

* لا يُعرض شراء أو بيع إلا من **نموذج مُتحقق منه** يحقق عائدًا متوقعًا متحفظًا موجبًا بعد العائد.
* المدة المقترحة هي صاحبة أعلى عائد متوقع متحفظ، بنفس قاعدة وضع AUTO.
* إن لم يتحقق ذلك فالقرار **انتظار**، مع السبب.
* حاليًا لا يوجد نموذج مُتحقق منه (انظر `docs/AUDIT_PHASE3.md`)، **لذلك ستكون القرارات «انتظار»**. هذا صحيح وليس عطلًا.

**قواعد ثابتة:**

* لا ثقة إلا من نموذج مُتحقق منه، ولا احتمال إلا إذا كان مُعايرًا.
* لا أسعار قديمة.
* Binance يُوسم «مرجعي — ليس أسعار ExpertOption ولا OTC».
* أسواق الفوركس وOTC تُعرض «غير متاحة»، لأنه لا يوجد مصدر بيانات مسموح لها.
* لا تداول حقيقي إطلاقًا.

**الحماية:**

* حد 6 تحليلات في الدقيقة لكل مستخدم.
* الطلب المكرر للسوق نفسه خلال 20 ثانية يعيد النتيجة نفسها دون تحليل جديد.
* الطلبات المتزامنة المتطابقة تشترك في تحليل واحد.
* حد أعلى للتحليلات المتوازية.
* مهلة 10 ثوانٍ؛ إن تعذر المحرك يرد البوت «تعذّر الوصول إلى محرك التحليل» دون أي قرار.

**بعد بدء التشغيل مباشرةً (أول دقيقتين):**

* تنزّل المنصة سجل 24 ساعة من Binance قبل البث الحي (نحو دقيقة).
* في هذه الفترة تظهر أسواق العملات الرقمية بالرمز ⏳ «قيد التحميل» بدل «غير متاحة»، ويقول التحليل «بيانات السوق قيد التحميل… أعد المحاولة بعد قليل»، والقرار يبقى **انتظار**.
* الأسواق التي لا مصدر مسموحًا لها (الفوركس وOTC والجسر معطّل) تبقى «غير متاحة» دائمًا، لأن بياناتها لن تصل.
* بعد انتهاء الفترة، أي سوق لم تصله بيانات يُعرض «غير متاح».

## 6. تعارض 409: نسختان من البوت بالرمز نفسه

Telegram يسمح لعملية واحدة فقط بالاستطلاع لكل رمز. إن شغّلت المنصة على جهازين (أو في نافذتين، أو محليًا وفي Docker معًا) يرد Telegram على إحداهما بالخطأ **409 Conflict** ويوزّع الرسائل بينهما، فتصبح الردود غير منتظمة.

المنصة تكشف ذلك تلقائيًا:

* **تنبيه حرج** واحد في سجل الأحداث (ويُرسل إلى `EO_ALERT_WEBHOOK` إن كان مضبوطًا).
* شارة **«Telegram: تعارض 409»** حمراء أعلى لوحة التحكم، وبطاقة «بوت Telegram» في صفحة «الاتصال والحالة».
* سطر «🔴 تعارض 409» في `/status` داخل البوت.
* البوت لا يتوقف: يواصل المحاولة، وعند إيقاف النسخة الأخرى يعود طبيعيًا خلال 90 ثانية ويُسجّل حدث «انتهى تعارض Telegram 409».

**الحل:** أوقف النسخة الأخرى (Task Scheduler أو `docker compose down` أو النافذة الأخرى). لا تحتاج تغيير الرمز.

## 7. حل المشكلات

| العَرَض | السبب والحل |
|---|---|
| `telegram-check` يقول `Unauthorized` | الرمز خاطئ أو أُلغي. انسخه من BotFather مجددًا |
| `NetworkError` / `ProxyError` | شبكتك أو جدار الحماية يحجب `api.telegram.org` |
| البوت يرد «غير مصرّح» | أضف معرّفك (الظاهر في الرسالة) إلى `EO_TELEGRAM_ALLOWED_USERS` وأعد التشغيل |
| لا رد إطلاقًا | تأكد أن `python -m eoplatform serve` يعمل، وأن الرمز في `.env`. صفحة «الاتصال والحالة» تعرض الخدمة `telegram_bot` |
| كل القرارات «انتظار» | متوقع حاليًا: لا يوجد نموذج اجتاز التحقق الإحصائي |
| ردود غير منتظمة / «تعارض 409» | نسخة ثانية تعمل بالرمز نفسه — انظر القسم 6 |
| البوت لا يرد في مجموعة | مقصود: يعمل في المحادثات الخاصة فقط ويغادر المجموعات |
| تحذير «الرمز يخص @… وليس @EO_PredictorBot» | نسخت رمز بوت آخر من BotFather. انسخ رمز EO_PredictorBot |
| ⏳ «قيد التحميل» | طبيعي في أول دقيقتين بعد التشغيل |
