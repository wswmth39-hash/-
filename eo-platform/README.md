# منصة تحليل ExpertOption بالذكاء الاصطناعي (مبنية على TradingAgents)

منصة ويب عربية تعمل باستمرار. تحلل أسواق ExpertOption (العادية وOTC) وتصدر **شراء / بيع / انتظار** لمدد 30 ث و1 و2 و5 دقائق.
تعتمد على محرك Python سريع، وعلى فريق وكلاء مبني على بنية [TradingAgents](https://github.com/TauricResearch/TradingAgents) ويعمل بنموذج لغوي محلي (Qwen عبر Ollama).

> **إشارات وتداول ورقي فقط.** لا يوجد في الكود أي مسار لتنفيذ صفقة حقيقية.
> لا يوجد أي ضمان للربح. الثقة المعروضة هي دقة مقاسة على بيانات لم يتدرب عليها النموذج، ولا تظهر إلا حين تتوفر عينة كافية.

## 1. ما الذي تحقق منه فعلًا وما الذي لم يُتحقق منه

بيئة البناء سحابية، وشبكتها تحجب `expertoption.com` و`ollama.com` وBinance وHugging Face (البروكسي يرد 403، مُثبت في السجل). ورُفض طلب فتح هذه المواقع. لذلك:

| البند | الحالة | الدليل |

## 2. تكامل ExpertOption: ما هو مشروع وما هو غير مشروع

* **لا توجد واجهة برمجية رسمية** (بحث نوفمبر 2026).
* مكتبات «ExpertOption API» المنشورة غير رسمية: تعيد استخدام رمز جلستك مع البروتوكول الخاص بالمنصة، وبعضها ينفّذ صفقات. **لم تُستخدم**، التزامًا بشرطك عدم تجاوز القيود.
* **البديل المطبق:** سكربت جسر يعمل داخل تبويبك المسجّل الدخول. يقرأ فقط الأسعار التي تستقبلها صفحتك أصلًا، ويرسلها إلى خادمك المحلي، ولا يرسل أي شيء إلى المنصة (مختبر).
  راجع شروط ExpertOption لحسابك.
* **OTC:** تُقبل بيانات ExpertOption فقط، مفروض في 4 أماكن: الكتالوج، و`allowed_sources`، ومزوّد Binance (assert)، والاستيراد. ولا تُستبدل بها أسعار الفوركس العادية أبدًا.
* **الأسواق العادية للعملات الرقمية:** يمكن استخدام Binance كمصدر **مرجعي** بوسم واضح في كل مكان. لا يُخلط مع بيانات ExpertOption في سلسلة واحدة، ولا يُطبَّق نموذج دُرّب على مصدر ما على مصدر آخر.
* **الفوركس العادي والسلع:** لا يوجد مصدر مجاني لحظي موثوق دون مفتاح، فتأتي بياناتها من الجسر فقط.
* **حدود صريحة:** بيانات ExpertOption لا تصل إلا ما دام تبويب المنصة مفتوحًا، فهي لا توجد في مكان آخر. أما الخادم والمراقبة والتقييم فتعمل دون أي متصفح.

## 3. البنية

```
              ┌──────────── متصفحك ─────────────┐
 ExpertOption │ bridge userscript (قراءة فقط)    │──POST /api/bridge/ingest (رمز Bearer)──┐
              └──────────────────────────────────┘                                        ▼
 Binance (مرجعي) ── WS kline_1s + REST ──►  DataHub: شموع 1 ث لكل (سوق، مصدر) + آلة حالات الحداثة ──► SQLite (WAL)
                                                 │
                    ┌────────────────────────────┴───────────────────────┐
                    ▼                                                    ▼
   المحرك السريع (≈25ms): مؤشرات + أنماط شموع + سيولة          فريق الوكلاء (LangGraph، بنية TradingAgents):
   + XGBoost البطل + بوابات (حداثة، تحقق، عتبة، تقلب)            6 محللين بالتوازي → مناظرة متفائل⇄متشائم (ConditionalLogic الأصلي)
          │                                                     → مدير البحث → مناظرة المخاطر (هجومي/متحفظ/محايد)
          │                                                     → وكيل إدارة المخاطر → وكيل القرار النهائي (بحواجز)
          └──────────────► كل إشارة تُسجَّل (لكل محرك على حدة) ◄────┘
                                   │
           المقيِّم: سعر حقيقي عند الانتهاء من نفس المصدر → ربح/خسارة/تعادل/ملغاة
                                   │
           التعلم: إحصاءات + أنماط الفشل + استراتيجيات بديلة + تدريب Walk-forward
                   + بطل/متحدٍّ + سحب النموذج عند تدهور أدائه الحي
```

### ما أُعيد استخدامه من TradingAgents وما تغيّر

* **أُعيد استخدامه كما هو:**
  * `create_llm_client` (مزوّد ollama).
  * `InvestDebateState` و`RiskDebateState`.
  * `ConditionalLogic` لتوجيه المناظرتين.
  * شكل الرسم البياني: محللون بالتوازي ← مناظرة ← مدير ← مناظرة مخاطر ← قرار.
* **استُبدل:** محللو الأخبار والأساسيات والمشاعر. صفقة مدتها 30 ثانية لا تحركها تقارير الشركات، فحلّ محلهم 6 متخصصين في البنية الدقيقة للسعر.
* **باقٍ ومتاح:** إطار TradingAgents الأصلي كاملًا (الأسهم، والواجهة السطرية الخاصة به) في `vendor/`.
* **التأريض:** كل وكيل يتلقى حقائق رقمية محسوبة. النموذج اللغوي يفسّر ويجادل ولا يخترع بيانات.
  ولا يستطيع وكيل القرار النهائي اختيار اتجاه يخالف الأدلة أو موانع المخاطر؛ أي مخالفة تتحول إلى «انتظار» وتُسجَّل.

## 4. سياسة القرار والثقة

* لا إشارة إلا على بيانات **حية**: آخر تحديث حقيقي خلال 3 ثوان.
* ولا إشارة دون 60 شمعة متتالية بلا فجوات.
* لا يُنشر اتجاه (`EO_REQUIRE_VALIDATED_MODEL=true`) إلا بوجود نموذج بطل:
  * دقته خارج العينة أعلى من **نقطة التعادل** (1/(1+العائد) = 55.6% بعائد 80%).
  * بحد أدنى للثقة مصحح للمقارنات المتعددة (Bonferroni، z=2.64).
* **الثقة** = الدقة الفعلية خارج العينة لتوقعات بقوة التوقع الحالي نفسها، مع عدد العينات والحد الأدنى 95%. ليست احتمال النموذج الخام.
* الاتجاه المرشح يُسجَّل ويُقيَّم دائمًا، حتى عند «انتظار»، ليتعلم النظام من كل شيء.
* **فريق الوكلاء** يخضع للقاعدة نفسها: لا يُنشر اتجاهه قبل أن يثبت سجله الحي.

## 5. لماذا البوابة صارمة (قياس، لا افتراض)

اختُبرت البوابة الأولى (حد أدنى > 50% ودقة ≥ التعادل) على **مشي عشوائي بحت**، فرقّت نموذجًا في **3 من 24** تجربة (12.5%). أي أنها كانت ستعرض ثقة زائفة.
البوابة الحالية لم ترقِّ أي نموذج في **0 من 24**، ووجدت الأفضلية المزروعة عمدًا في **8 من 8**.
الاختباران دائمان في `tests/test_engine_learning.py`.

**توقّع واقعي:** على أسعار حقيقية قصيرة المدى، قد لا يجتاز أي نموذج هذه البوابة، فتكون النتيجة «انتظار» معظم الوقت. هذه هي النتيجة الصادقة.

## 6. التشغيل على جهازك

```bash
cd eo-platform
python3 -m venv .venv && . .venv/bin/activate
pip install -e vendor/TradingAgents -r requirements.txt
cp .env.example .env                       # عدّل العائد والنموذج حسب حاجتك
# النموذج المحلي (مجاني): https://ollama.com/download
ollama pull qwen3.5:9b                     # إن كانت الذاكرة < 16GB جرّب qwen3.5:4b واضبط EO_LLM_MODEL
python -m eoplatform check-system          # العتاد، Ollama، سرعة النموذج، زمن الفريق المتوقع
python -m eoplatform check-sources         # يتحقق فعليًا من Binance والنموذج المحلي من جهازك
python -m eoplatform create-admin          # كلمة مرور الموقع (تُحفظ كـscrypt فقط)
python -m eoplatform serve                 # http://127.0.0.1:8000
```

ثم من الموقع ← الإعدادات ← «إنشاء رمز جسر»، واتبع `bridge/README.md`.

**تشغيل دائم:**

* Linux: `sudo deploy/install.sh` — خدمة systemd بإعادة تشغيل تلقائية وحدود موارد.
* أو Docker: `docker compose up -d` (التطبيق + Ollama، `restart: unless-stopped`، فحص صحة).

**أوامر إضافية:**

| الأمر | الغرض |
|---|---|
| `import-csv` | بيانات تاريخية حقيقية لديك |
| `retrain` | تدريب وتحقق Walk-forward يدويًا |
| `analyze --market EURUSD_OTC --duration 60` | تحليل من سطر الأوامر |

**الوصول من خارج الجهاز:** الخادم يستمع على 127.0.0.1. للوصول من الجوال استخدم وكيلًا عكسيًا بـHTTPS واضبط `EO_COOKIE_SECURE=true`.

## 7. الأمان

* الأسرار في متغيرات البيئة أو `.env` (مستبعد من git). سر الجلسة يُولَّد تلقائيًا بصلاحية 0600.
* لا يُخزَّن أي كلمة مرور لـExpertOption، فالجسر لا يحتاجها.
* كلمات مرور الموقع مخزنة كـscrypt فقط، والجلسة في كوكي HttpOnly + SameSite=Strict.
* حماية CSRF (double-submit)، وتقييد محاولات الدخول، ورأس CSP صارم دون سكربتات مضمّنة.
* رموز الجسر مخزنة كهاش SHA-256، ويمكن إلغاؤها.
* لا مفاتيح في الواجهة (مختبر).
* لا يُقبل مزوّد نموذج لغوي مدفوع: ollama وopenai_compatible المحلي فقط.
